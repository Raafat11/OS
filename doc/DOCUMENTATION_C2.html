Project Overview

This project compares two CPU scheduling algorithms: SRTF (Shortest Remaining Time First — Preemptive) and Round Robin (RR — Preemptive with Time Quantum = 2). Both algorithms are executed on the exact same workload to ensure a valid and fair comparison.

The goal is to analyze the difference between a scheduler that always selects the process with the shortest remaining burst time and one that distributes CPU time equally among all ready processes using a fixed time quantum, and to evaluate how each affects waiting time, response time, and turnaround time.

2

Algorithm Descriptions

⚡ SRTF — Shortest Remaining Time First (Preemptive)

  • Always selects the process with the shortest remaining burst time from the ready queue
  • Preemptive: if a new process arrives with a shorter remaining burst time than the currently running one, it is immediately preempted
  • Also known as SRTN (Shortest Remaining Time Next)
  • Goal: to minimize the average waiting time for all processes
  • Tie-breaking: equal remaining burst time → earlier arrival time wins; if still tied → alphabetical Process ID

🕒 RR — Round Robin (Preemptive)

  • Time Quantum (TQ = 2): each process is assigned a fixed time unit. The CPU switches between processes after every TQ
  • Preemptive: a process is preempted once its time quantum expires and is moved to the back of the ready queue
  • Fairness: ensures no process waits too long and prevents starvation
  • Performance depends heavily on TQ value: too large → behaves like FCFS; too small → excessive context switching
  • Tie-breaking: if a new process arrives exactly when a TQ expires, the new arrival is added to the queue first, followed by the preempted process
3

Metrics Calculated

CT — Completion Time
time when process finishes
The exact time at which the process finishes its execution on the CPU
TAT — Turnaround Time
TAT = CT − Arrival Time
Total time from when the process arrived until it completed execution
WT — Waiting Time
WT = TAT − Burst Time
Total time the process spent waiting in the ready queue without executing
RT — Response Time
RT = First CPU Time − Arrival Time
Time from when the process arrived until it first received CPU execution
4

Implementation Rules

Time Quantum Rule: Round Robin uses a fixed Time Quantum (TQ = 2). Each process runs for at most 2 time units before being preempted and moved to the back of the ready queue.
Preemption Rule (SRTF): The running process is interrupted immediately when a newly arrived process has a shorter remaining burst time.
Preemption Rule (RR): The running process is preempted after exactly TQ time units expire, regardless of its remaining burst time.
Tie-Breaking Rule (SRTF): Equal remaining burst time → earlier arrival time wins. If arrival times also match → alphabetical Process ID.
Tie-Breaking Rule (RR): When a new process arrives exactly as a quantum expires, the new arrival enters the queue before the preempted process.
Same Workload Rule: Both algorithms must run on the exact same set of processes. A comparison is invalid if different datasets are used.

Input Validation

The simulator validates all input before the simulation begins and rejects any invalid data with a clear error message.

❌Zero or Negative Burst Time: rejected — must be ≥ 1
❌Time Quantum < 1: rejected — TQ must be at least 1 (system shows: "Time Quantum must be at least 1")
❌Duplicate Process ID: rejected — each process must have a unique ID
❌Empty Fields: rejected — all fields (PID, Arrival Time, Burst Time) are required
❌Non-numeric Values in Numeric Fields: rejected
✅Valid Input: unique PID, AT ≥ 0, BT ≥ 1, TQ ≥ 1

Conclusion & Recommendation

Final Conclusion

SRTF (Preemptive) achieved better results in terms of average waiting time and average turnaround time across all tested scenarios. By always executing the process with the shortest remaining burst time, SRTF minimizes waiting time for short processes and delivers the highest overall CPU efficiency.

Round Robin ensures every process receives CPU time within a bounded interval (TQ = 2), making it the clear winner in response time fairness and starvation prevention. Scenario D demonstrated this perfectly — when all burst times are equal, RR's first-response time (2.00) vastly outperforms SRTF's (20.00).

Main Trade-off: SRTF optimizes overall efficiency (lower average WT and TAT), while Round Robin optimizes fairness and interactivity (guarantees timely response for all processes). The right choice depends on the system's primary goal.

Recommendation for the tested workloads: SRTF — it produced lower average waiting time and turnaround time in 4 out of 5 scenarios, making it more efficient for general-purpose workloads. However, Round Robin is the better choice for interactive or time-sharing systems where fairness and fast response time matter more than raw efficiency.
